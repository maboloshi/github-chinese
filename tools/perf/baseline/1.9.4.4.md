## 读数时的注意事项

- **确定性只到 `search-open` 之前**：重跑时 `after-load`、`hover-issues`（+194）、`menu-open`、
  `menu-close`、`settle-3s`（+194）逐位相同；`search-*` 之后按打字落点波动。**A/B 只比较确定性那一段。**
- `idle-10s` 可能撞上 GitHub 自己的轮询（实测某次出现 +123 回调 / +715 记录 / +1727 节点），
  那不是脚本的稳态开销。看稳态要看 `settle-3s` 与 `idle-10s` 的回调数是否为 0。
- `longTasks` 统计的是整页长任务，包含 GitHub 自己的活，不是脚本独占开销。

## 从基线读出的三件事

1. **空闲时开销为 0，但收尾时仍在走树**：`settle-3s` 回调与记录都不增长，遍历节点却 +194
   （压力场景收尾排的那次 400ms 重试）；到 `idle-10s` 才真正归零。
2. **事件触发的全量重走是最大纯浪费**：`hover-issues` 阶段 MO 回调 +1、记录 +2，却遍历 194 个节点。
   根因是头部模块 4 个捕获阶段监听里的 `pointerover`——**开销 ∝ 事件频率，而非 ∝ 变化量**。
   第 1 步已移除它，实测该阶段遍历节点由 +194 降到 0。
3. **单位成本 ≈ 0.095 ms / 条 mutation**（`after-load` 116.1ms / 1223 条）。

另外两项待查（不影响上述结论）：

- `revertWrites=2`：有 2 次「写进去又被改回原值」，说明确实存在 React 回写，量很小但要弄清是哪两处。
- `被删的已写节点=1`：React 删掉了一个我们译过的节点。当前没有引发 `NotFoundError`，
  但这正是「破坏节点身份会炸」的那条路径，改造期间要盯着这个数别涨。

## 更正：init() 的注入时机不是脚本缺陷

曾记录「`init()` 在 `initLangEnv` 处中断」，复测证明是**基准台伪影**：

| 注入时机 | documentElement | head | body | readyState |
|---|---|---|---|---|
| CDP `addScriptToEvaluateOnNewDocument` | false | false | false | loading |
| content-script `run_at=document_start`（Tampermonkey 用的时机） | **true** | false | false | loading |

Tampermonkey 下 `documentElement` 已存在，`initLangEnv` 正常，`init()` 完整执行。
基准台已改为「等 `documentElement` 出现再启动主脚本」以对齐真实时序（见
[`../lib/instrument.mjs`](../lib/instrument.mjs) 的 `buildBootstrap`）。
该项从「缺陷」降级为「仅在更早注入时机下才暴露的隐式前提」，不计入重构范围。

## 仍然成立的实测发现

1. **搜索弹层选择器过时**：脚本查 `#search-suggestions-dialog` / `qbsearch-input` /
   `.ActionList-sectionDivider-title` / `.search-feedback-prompt`；现行页面是
   `#__primerPortalRoot__ .quick-search-overlay-module__Panel__`（输入框 `prc-components-Input-*`）。
   基准里 `dialog` 始终为 `false`，而弹层内的中文却正常出现——中文来自通用通道，
   `translateReactGlobalNavSearchDialog()` 是死代码。
2. **销毁式写入 14 次**：`after-load` 就发生 14 次 `textContent =`（作用于已有子节点的元素）。
   这次压力测试里 `removeChild` 错误为 0，但这是要靠「改成就地写」消掉的量。
3. **Q1 结论**：当前「抢」策略在真实登录态下 回写只有 2、被删已写节点 1、
   `removeChild`/`insertBefore` 异常 0；空闲 10s 为 0 开销。替换式写入可以继续用，
   回写监控降级为安全网。
4. **提示气泡不由头部模块翻译**：现在的实现是 `<tool-tip for="...">` 自定义元素（平时
   `display:none`，文案放在宿主元素的 light DOM），头部模块的 `#__primerPortalRoot__ [role="tooltip"]`
   从来匹配不到它。实测 `header.GlobalNav` 内没有任何 `<tool-tip>`；页面上另一个
   `Dismiss alert`（警报关闭按钮）仍是英文——与本模块无关，记入待查。
